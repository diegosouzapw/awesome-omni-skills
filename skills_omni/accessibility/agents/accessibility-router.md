# Accessibility router guidance

Use this skill when the primary task is auditing or improving web accessibility.

## Stay in accessibility when

- the main issue is keyboard use, focus, semantics, screen readers, forms, contrast, motion, or dynamic announcements
- the user wants WCAG-oriented findings or remediation guidance
- the work centers on accessible components or journeys

## Route to another skill when

- the request becomes a broad quality review across multiple domains: use `@web-quality-audit`
- the primary concern is performance or loading behavior: use `@core-web-vitals`
- the primary concern is search ranking or discoverability: use `@seo`

## Cross-functional note

Some issues, especially authentication, repeated entry, CAPTCHAs, and security friction, may require product and security decisions in addition to accessibility remediation. Record those dependencies explicitly instead of treating them as code-only fixes.
