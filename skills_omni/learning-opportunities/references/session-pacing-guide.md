# Session Pacing Guide

Use this guide to keep learning support lightweight and welcome.

## Offer Frequency

- Prefer no more than one unsolicited learning prompt after a significant change.
- Avoid offering more than two exercises in one session unless the user explicitly asks for more.
- If the user declines twice, stop offering for the rest of the session.

## Depth Levels

### 30-second

Use for:

- quick behavior prediction
- one-file understanding checks
- post-refactor ownership clarification

### 2-minute

Use for:

- one question plus one follow-up
- comparing a design sketch to implementation
- tracing one code path or migration effect

### Skip

Use when:

- the user wants speed
- the task is already heavy
- the timing is wrong

## Good pacing signals

- the user asks why
- the user shows curiosity
- a new abstraction just appeared
- the lesson immediately improves current work quality

## Bad pacing signals

- active incident response
- repeated user impatience
- many failing tests and high urgency
- explanation is becoming longer than the work itself
