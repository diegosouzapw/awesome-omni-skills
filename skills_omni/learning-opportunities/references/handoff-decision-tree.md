# Handoff Decision Tree

Use this when the session stops being primarily about learning support.

## Route to debugging

Choose this if:

- the main goal is finding the cause of a failure
- tests are failing and speed matters
- the system is unhealthy or production-facing

## Route to architecture

Choose this if:

- the main goal is evaluating boundaries or tradeoffs
- multiple designs are under consideration
- the conversation is mostly about long-term maintainability

## Route to testing

Choose this if:

- the user needs a test plan
- the session is about missing cases or coverage
- correctness evidence matters more than explanation style

## Route to documentation

Choose this if:

- the explanation should become durable written documentation
- the user needs a guide, ADR, README, or migration note

## Route to security review

Choose this if:

- auth, secrets, trust boundaries, or data exposure become central
- the risk analysis is more important than the exercise itself

## Route to onboarding

Choose this if:

- the user needs a broader map of the codebase
- many connected systems need orientation, not one local concept
