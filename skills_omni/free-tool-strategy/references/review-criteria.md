# Free Tool Review Criteria

Use this rubric to evaluate a proposed or existing free tool quickly. Score each area from **0 to 2**:

- **0 = weak or missing**
- **1 = partial or uncertain**
- **2 = strong and evidenced**

Suggested interpretation:

- **15–20:** strong candidate
- **10–14:** promising but needs revision
- **0–9:** weak candidate or wrong strategy

## 1. User Utility

| Check | What to ask | Score |
|---|---|---|
| Concrete problem | Does the tool solve a narrow, real task rather than entertain or decorate? | 0–2 |
| Time to value | Can a user understand and start getting value quickly? | 0–2 |
| Actionable output | Does the result help the user decide, estimate, compare, or do something useful next? | 0–2 |

Red flags:

- novelty with no recurring use case
- vague output that sounds impressive but does not support action
- long setup before the user sees value

## 2. Audience and Commercial Fit

| Check | What to ask | Score |
|---|---|---|
| Right audience | Does the tool attract people relevant to the business? | 0–2 |
| Intent quality | Is the use case adjacent to a buying problem, budget problem, or category problem? | 0–2 |
| Brand fit | Is the company credible in this problem space? | 0–2 |

Red flags:

- large traffic potential but weak buyer relevance
- audience mismatch between tool users and product buyers
- brand enters a problem space it cannot credibly support

## 3. Search Integrity and Discoverability

| Check | What to ask | Score |
|---|---|---|
| Searchable task | Is there believable search or referral demand for the task? | 0–2 |
| People-first page | Would the page remain useful even without rankings? | 0–2 |
| Originality | Is the page more than a templated wrapper around trivial logic? | 0–2 |

Red flags:

- idea exists mainly to generate indexable pages
- scaled low-value content strategy
- interchangeable copy across many pages or variants
- thin tool surrounded by inflated SEO text

## 4. UX and Trust

| Check | What to ask | Score |
|---|---|---|
| Clarity | Can the user understand what the tool does before interacting? | 0–2 |
| Credibility | Are assumptions, limitations, or data freshness visible where needed? | 0–2 |
| Friction control | Are inputs limited to what is genuinely necessary? | 0–2 |

Red flags:

- misleading labels or deceptive form patterns
- hidden assumptions that make results feel arbitrary
- basic utility blocked before the user can evaluate value

## 5. Lead-Capture Integrity

| Check | What to ask | Score |
|---|---|---|
| Fair exchange | Does the user get enough value before any gate? | 0–2 |
| Relevance of ask | Are requested fields justified by the use case? | 0–2 |
| Follow-up honesty | Is it clear what happens after submission? | 0–2 |

Red flags:

- forced email submission before any meaningful output
- collecting extra fields only to inflate MQL counts
- consent or follow-up language that is vague or bundled

## 6. Measurement Readiness

| Check | What to ask | Score |
|---|---|---|
| Core events defined | Are start, completion, key action, and lead events specified? | 0–2 |
| Outcome linkage | Can the team connect usage to lead quality or downstream business outcomes? | 0–2 |
| Ownership | Is someone accountable for reviewing results after launch? | 0–2 |

Red flags:

- launch planned without event definitions
- success judged only by pageviews
- no plan for reviewing lead quality versus raw volume

## Fast Pass / Fail Questions

If any answer is **no**, pause the launch or request revision:

1. Can you name the exact user and the exact problem in one sentence?
2. Would the page still be worth publishing if it never ranked?
3. Can the user receive meaningful value before being pushed into a form?
4. Can the team measure tool usage and lead outcomes clearly?
5. Is the attracted audience likely to matter to the business?

## Decision Shortcuts

### Recommend build now

Use when:

- user utility is strong
- audience quality is high
- the page can stand on its own merit
- trust and measurement are well designed

### Recommend revise before build

Use when:

- concept is good but gating is too aggressive
- outputs are too generic
- discoverability or instrumentation is still unclear

### Recommend reject

Use when:

- the tool is mostly an SEO vehicle
- business relevance is weak
- novelty outweighs practical usefulness
- maintenance burden exceeds strategic upside
