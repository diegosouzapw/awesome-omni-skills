# SEO router

Use this note when the request is close to SEO but the dominant work belongs elsewhere.

## Stay in @seo when

- the issue is crawlability, indexing, canonicalization, metadata, sitemap quality, structured data, or hreflang
- the agent can verify the work through HTML, headers, sitemaps, and Search Console evidence

## Hand off to adjacent skills when

- `@core-web-vitals`: the main concern is loading speed, rendering stability, or responsiveness
- `@web-accessibility`: the main concern is semantic accessibility, focus order, labeling, or assistive-technology support
- `@web-quality-audit`: the request is a broad audit across SEO, performance, accessibility, analytics, content quality, and UX

## Mixed cases

If SEO is blocked by another discipline:

1. document the SEO symptom
2. note the blocking cause
3. hand off to the adjacent skill
4. return to `@seo` for final validation once the blocker is resolved
