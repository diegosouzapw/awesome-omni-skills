## Guardrails

A PQL is weak if it relies on:

- generic activity without intent
- vanity events with no relation to buying or expansion
- one-off clicks on billing or pricing pages without deeper usage
- engagement before activation

## Review Table

| Field | Decision |
| --- | --- |
| Trigger is observable and reliable | yes / no |
| Trigger happens after meaningful usage | yes / no |
| Sales can add distinct value | yes / no |
| Threshold is specific enough to avoid spam | yes / no |
| Response owner is clear | yes / no |
| Success metric is defined | yes / no |

## Example Trigger Types

- multiple active users from one domain
- repeated use of collaboration or admin features
- feature gate hit on enterprise controls
- production deployment or sustained usage threshold
- expansion request from an existing free or paid team
